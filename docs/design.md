## 1. 目的と背景

### 1.1 なぜ作るか [決定]

- ユーザーは現在 Pico 4 Ultra を使い、PICO Connect(SteamVR ドライバとして動く)で SteamVR に接続している。
- 近いうちに Bigscreen Beyond 2e を購入する予定。
- Beyond を使う日は PICO Connect を無効にする必要がある。今は「SteamVR を開く → プラグインをオフ → SteamVR を再起動」、または設定ファイルを手で編集している。どちらも時間と手間がかかる。
- これを、ソフトからワンアクションで切り替えられるようにしたい。

### 1.2 使い方の前提 [決定]

- Pico だけ使う日と Beyond だけ使う日がある。**同時には使わない。**
- ソフトの中心は「Pico モード」「Beyond モード」の切り替え。

---

## 2. スコープ

### 2.1 ゴール(第1段階 = 核) [決定]

1. PICO Connect の有効/無効を切り替える(Pico モード / Beyond モード)。
2. 操作はウィンドウとタスクトレイの両方から行える。
3. 常駐するため、軽量に動く。

### 2.2 切り替え時の挙動 [決定]

- SteamVR が起動中に切り替えようとしたら、確認ダイアログを出す。選択肢は次の3つ。
    - **再起動**: SteamVR を終了 → 設定を書き換え → SteamVR を再度起動する
    - **手動でやる**: 設定だけ書き換え、再起動はユーザーが行う
    - **キャンセル**: 何もしない
- SteamVR が起動していないときの挙動は未指定。**[提案]** 確認なしで設定だけ書き換える。

### 2.5 アンチゴール(これが起きたら失敗)

- **[提案]** SteamVR や PICO Connect の設定ファイルを壊す。書き換え前にバックアップを取り、書き換えに失敗したら元に戻せること。
- **[提案]** VR の最中に誤操作で SteamVR が落ちる。確認ダイアログがこれを防ぐ。
- **[提案]** 常駐ソフトが重くて、ゲームの邪魔になる。

## 3. 制約

- 対象 OS は Windows(SteamVR と PICO Connect の前提)。**[提案]**
- 常駐前提のため、メモリと CPU の使用量をなるべく小さくする。[決定]
- 将来の機能追加(通知、バッテリー、機器状態)を足しやすい構造にする。[決定]

## 4. 技術の選択肢(Approaches)

ユーザーは「軽量に動く言語がいい」と指定した。その上で、**UI 技術は WinForms で進めることをユーザーが決定した**(2026-11-20、「今の段階は WinForms で行く」)。将来見た目を凝りたくなったときは、画面部分だけ WPF などに差し替える余地を残す(切り替え処理は画面と分離して作る)。

WinForms / WPF / WinUI 3 の比較(軽さは WinForms > WPF ≒ WinUI 3 が一般的な傾向。実測は未確認):WinForms は OS 標準の部品を使うため最も軽く、WPF と WinUI 3 は独自の描画エンジンを持つ分だけ重い。WinUI 3 は Windows App SDK の同梱で配布も大きくなる。

以下の表のうち、言語の選定(C#)は **Claude の提案**であり、ユーザーが個別に承認したものではない。

| 案                                                                      | 長所                                                                                                                                  | 短所                                              |
| ----------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------- |
| **A. C# (.NET) + WinForms** ← 採用(言語は提案、WinForms はユーザー決定) | Windows のウィンドウとタスクトレイが標準で扱える。WPF より軽い。OpenVR の C# 向けライブラリがあり、将来のバッテリー取得に繋げやすい。 | 開発に .NET の環境が要る                          |
| B. Python + PySide など                                                 | 書くのが速い。OpenVR の Python 向けライブラリもある                                                                                   | exe 化が面倒で、常駐時に重くなりやすい            |
| C. Electron / Tauri                                                     | 見た目の自由度が高い                                                                                                                  | 切り替えだけのツールには重く、OpenVR 連携も遠回り |
| D. Rust / C++                                                           | さらに軽くできる                                                                                                                      | 開発コストが高い。今回は見送り                    |

採用理由: 軽量さと、将来の拡張性(OpenVR 連携)と、開発の手軽さのバランスが最も良い。

### 将来の検討事項

- 機能が増えて OyasumiVR のような多機能ツールに育てたくなった場合は、画面部分を Tauri などの Web 技術に作り直す選択肢がある。現時点では**方向未定**(ユーザーも「わからない」と回答)で、まず小さな切り替えツールとして作る。

## 5. 確認が必要な事項(VR用PCで調べる)

VR用PCでの確認結果(2026-11-20)。**[確認済]** は実機で確認できたもの。下の元の項目リストは参照用に残す。

### 5.1 確認結果

| #   | 項目                  | 結果                                                                                                                                                                                                                                             |
| --- | --------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| 1   | 有効/無効を決める場所 | **[確認済]** `<Steamのインストール先>\config\steamvr.vrsettings` の `driver_pico` セクション。無効時は `"enable": false` が入り、有効時はセクションごと無い。書き換えは JSON の項目の追加/削除で済む                                              |
| 2   | ファイルの場所        | **[確認済]** `<Steamのインストール先>\config\steamvr.vrsettings`。インストール先はレジストリ `HKCU\Software\Valve\Steam` の `SteamPath` で取得できた(区切りが `/` で小文字なので、パス正規化が必要)。**[提案]** 取れなければユーザーに入力させる |
| 3   | 反映のタイミング      | **[確認済]** SteamVR 終了中に書き換えれば反映される。起動中に書き換えた場合は再起動が必要                                                                                                                                                        |
| 4   | 終了・起動            | 終了: `vrmonitor` のウィンドウを閉じれば終了する。起動: `steam://rungameid/250820`、または `vrstartup.exe`(`SteamVR\bin` 内に存在を確認)。プロセス名は `vrmonitor.exe` のほか `vrserver.exe` などが存在                                            |
| 5   | Beyond 2e の追加設定  | **[未確認]** Beyond 2e の購入後に確認                                                                                                                                                                                                            |
| 6   | インストール先の検出  | 現状の方針はユーザーが path を入力。**[提案]** 既定はレジストリから自動検出し、失敗時だけ入力させる                                                                                                                                              |

### 5.2 起動中の判定方法 **[提案]**

- `vrserver.exe`(SteamVR の本体)または `vrmonitor.exe`(ウィンドウ)のプロセスが存在するかで判定する。.NET なら `Process.GetProcessesByName("vrserver")`。
- 切り替えの前提としては、ウィンドウを閉じれば終了するため `vrmonitor` を基準にし、`vrserver` が残っていないことも確認する。終了待ちはプロセスが消えるまで一定時間ポーリングする。

### 5.3 元の確認項目(参照用)

1. PICO Connect の有効/無効は、どのファイルのどの項目で決まるか。
    - 候補: SteamVR の設定ファイル(`steamvr.vrsettings`)、または `openvrpaths.vrpath` のドライバ登録。
    - SteamVR の「アドオン」画面での有効/無効が、実際にどのファイルを書き換えているか。
2. その設定ファイルの場所(Steam のインストール先がユーザーごとに異なる点も含めて)。
3. 設定を書き換えただけで反映されるか、SteamVR の再起動が必須か。
4. SteamVR を安全に終了・起動する方法(プロセス名、`steam://` URL での起動など)。
5. Beyond 2e を使うときに、PICO Connect 以外に切り替えが必要な設定があるか。
6. Steam のインストール先の検出方法(レジストリなど)。
